# OSINT-радар — приватный Telegram-канал о том, что набирает популярность в OSINT

Автономная редакция приватного канала для собственной журналистской работы. Каждый час она ищет OSINT-инструменты, методы, расследования, утечки и изменения платформ, которые прямо сейчас набирают внимание. Затем измеряет скорость их роста, оценивает значимость по шкале 1–10 и сама публикует посты. Вечером выходит дайджест дня.

Устроен так же, как [vibe-radar](https://github.com/Igoryanich/vibe-radar) и russia-nato-monitor: Node 24 + TypeScript без сборки, SQLite в ветке `state`, Gemini с цепочкой моделей и фоллбэком, GitHub Actions. Работает бесплатно, компьютер для этого не нужен. Редакционные правила лежат в [prompts/system.md](prompts/system.md).

## Как это работает

```
~130 источников (config/sources.yaml):
  GitHub Trending + молодые репозитории по темам osint/recon/threat-intel + релизы известных инструментов,
  Hacker News, Reddit (14 сабреддитов), блоги и гайды (Bellingcat, OSINT Team, IntelTechniques, Medium, Хабр…),
  исследовательские редакции (DFRLab, Citizen Lab, ICIJ, The Insider…), пресса по безопасности,
  Mastodon #osint, 13 Telegram-каналов
 → одна вещь на разных площадках = один кандидат (репо + тред на Reddit + пост в Telegram)
 → гайд, расследование или тред без ссылки на код = отдельный «материал» (story:)
 → снимки счётчиков каждый час → прирост звёзд/очков/апвоутов за 24 и 72 часа    (код, без AI)
 → предварительный отбор: топ-30
 → scan (Gemini): HYPE_SCORE 1–10, категория, стадия, статус, риски, доступность
 → пороги проверяет код: пост при ≥7, или ≥6 + «ранний сигнал» + измеренная аномальная скорость
 → текст поста (Gemini) → жёсткие проверки → очередь → Telegram
 → после 21:00 по Хельсинки — дайджест дня
```

Категории: инструмент · метод · расследование · источник данных (включая утечки) · изменение платформы · слежка и рынок данных.

## Редакционные гарантии (проверяются кодом)

- **Скорость не угадывается.** Все дельты считаются по нашим снимкам счётчиков.
- **Цифры не выдумываются.** Каждое число ≥ 100 в тексте должно совпадать (±5%) с собранными данными: счётчиками или текстом самого материала. Иначе текст переписывается; если и со второй попытки не вышло, пост не публикуется.
- **Ссылки только настоящие.** В пост попадают только URL, которые видели сборщики, и ссылки на наши же посты.
- **Пороги задаёт код.** Пост выходит при оценке ≥ 5 (настройка `POST_THRESHOLD`); статусы модели «skip» и «needs_check» блокируют публикацию.
- **Повтор выходит только с новостью.** Нужен рост в 3 раза или новость, и не раньше чем через 48 часов. Повтор публикуется ответом на исходный пост.
- **Формат проверяется.** Telegram HTML, лимит длины, текст на русском.

## Запуск

1. Создайте **приватный Telegram-канал**.
2. Создайте бота в @BotFather и добавьте его админом канала с правами «Публикация сообщений» и «Закрепление сообщений».
3. Узнайте числовой id канала (вида `-100…`): например, перешлите любой пост канала боту @userinfobot. У приватного канала нет `@имени`.
4. Создайте репозиторий на GitHub и загрузите туда проект.
   - **Публичный** репозиторий даёт бесплатные безлимитные минуты Actions. Но тогда видны код, источники и логи запусков, включая шаг «Latest texts» с текстами постов.
   - **Приватный** скрывает всё это, но не подходит: бесплатно в нём около 2000 минут в месяц, а радар работает круглосуточно (GitHub запускает расписание нерегулярно, поэтому один запуск сам крутит цикл каждый час около 5,5 часа).
5. В репозитории откройте **Settings → Secrets and variables → Actions**:
   - Secrets: `GEMINI_API_KEY` (лучше из отдельного Google Cloud проекта), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` (`-100…`).
   - Variables: `DRY_RUN` = `true` на первые сутки, `CHANNEL_NAME` = название канала.
6. Запустите workflow **radar** вручную (Actions → radar → Run workflow). Дальше он будет запускаться сам.
7. Через сутки посмотрите, что получилось бы (`npm run posts` локально или лог Actions). Если всё устраивает, поставьте `DRY_RUN` = `false`.

Первые часы постов почти не будет, и это нормально: для дельт за 24 часа нужны снимки за 24 часа. Сразу работают GitHub Trending, свежие репозитории, свежие треды и материалы из блогов.

Reddit с домашнего IP отвечает 403/429. Из GitHub Actions тот же сборщик работает (проверено в vibe-radar).

## Локально

```bash
npm install
cp .env.example .env        # впишите GEMINI_API_KEY
npm run collect             # собрать источники
node src/cli.ts sources     # какие источники что дали, ошибки
node src/cli.ts candidates  # что увидит scan
node src/cli.ts scan        # оценка
node src/cli.ts projects    # вердикты
node src/cli.ts posts-queue # написать посты (в DRY_RUN не отправляются)
npm run posts               # прочитать тексты
npm run check               # typecheck + тесты
```

## Настройка

| Что | Где |
|---|---|
| Источники | `config/sources.yaml` (меняются без правки кода; `standalone: true` — статьи источника становятся отдельными материалами) |
| Редакционный промпт | `prompts/system.md` |
| Эталон | `prompts/reference.md` |
| Опорные примеры для шкалы | `prompts/anchors.md` — добавляйте реальные случаи с баллами |
| Пороги, лимиты, час дайджеста | переменные окружения, см. `.env.example` |

## Чего нет

- **X/Twitter, Discord, YouTube.** У них нет бесплатного стабильного API. Их охват виден косвенно: через Telegram-каналы, Mastodon и прессу.
- **Веб-поиска при оценке.** Модель работает только с собранными данными, поэтому её выводы проверяемы.
